# S1 — Flow-ML diagram-as-code panel — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development or superpowers:executing-plans. Steps use `- [ ]`.

**Goal:** A left **Flow-ML** text panel that is the single source of truth for the board: edits to the text rebuild the diagram, and edits to the diagram re-serialize into the text, persisted as one localStorage blob.

**Architecture:** Two pure functions (`parse` text→model, `serialize` model→text, round-trippable) + a panel UI + a sync controller with an anti-loop guard. Text→diagram debounces a parse then re-renders the board from the model; diagram→text routes every mutation through a central `commit()` that re-serializes (canonical, v1) and saves. Backward-compatible: `init({ project })` is converted to Flow-ML internally.

**Tech Stack:** TypeScript, tsup, vitest+jsdom, CSS (`fb-` prefix).

---

## Flow-ML grammar (agreed)
One entity per line; type by leading token:
- `#` comment · `!key = value` project directive (`!name`) · `@id, attrs` epic · `id, attrs` screen · `a -> b, attrs` arrow.
- Attributes `k=v`, comma-separated, value quoted if it has spaces/commas. Flags (e.g. `d`) take no value.

| key | on | meaning |
|---|---|---|
| `t` | screen/epic | title / label |
| `p` `f` `e` `n` | screen | preset, format, epic id, notes |
| `x` `y` | screen | position |
| `h` | screen | hidden (flag) |
| `c` | epic | color |
| `l` `d` `fs` `ts` | arrow | label, dashed (flag), from/to side |

Screen `custom` HTML → a ```` ``` ```` fenced block immediately after the screen line.

## Model (parser output)
```ts
interface FlowDoc { project: FlowProject; positions: Record<string, Position>; }
parse(text: string): { doc: FlowDoc; errors: { line: number; msg: string }[] }
serialize(doc: FlowDoc): string   // canonical, deterministic order
```
`project` reuses `core/types` (name, epics, screens with preset/format/epic/notes/content/hidden, arrows). `positions` from `x`/`y`.

## File structure
```
src/flowml/parse.ts        (create)  tokenise + build FlowDoc, collect errors
src/flowml/serialize.ts    (create)  FlowDoc → canonical Flow-ML
src/render/panel.ts        (create)  left panel: header + collapse + <textarea>
src/interactions/sync.ts   (create)  initSync(): textarea→rebuild; commit(): diagram→text+save
src/board.ts               (modify)  build panel, load Flow-ML (or convert config.project), wire sync, rebuildBoard()
src/core/storage.ts        (modify)  saveDoc/loadDoc (fb-<name>-flowml); keep -view (zoom/pan); drop -pos/-arrowmods/-hidden
flowboard.css              (modify)  panel + collapse styles
flowboard.test.js          (modify)  parse/serialize/round-trip units
flowboard.interactions.test.js (modify) panel + sync (both directions, anti-loop)
```

## Persistence model
- **`fb-<name>-flowml`** = the text (schema: epics/screens/arrows/positions/presets/formats/notes/hidden/content). The single source of truth.
- **`fb-<name>-view`** = viewport only (zoom/pan). Not schema.
- Drop `-pos`, `-arrowmods`, `-hidden` (now in the text).

### Task 1.3: round-trip
- [ ] Test: `parse(serialize(doc)).doc` deep-equals `doc` for a rich fixture; `serialize(parse(text)).` is idempotent (serialize→parse→serialize stable).
